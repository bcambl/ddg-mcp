# Contributing to ddg-mcp

Thank you for your interest in contributing! This document outlines the process for contributing to the project.

## Development setup

```bash
git clone https://github.com/bcambl/ddg-mcp.git
cd ddg-mcp
make deps
```

## Making changes

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/my-feature`)
3. Make your changes
4. Ensure all checks pass: `make check`
5. Commit with a [conventional commit](#commit-messages) message **and** a `Signed-off-by` trailer (use `git commit -s`)
6. Push to your fork and open a pull request

## Code style

- Follow standard Go conventions and `gofmt` formatting
- Run `go vet` before committing — it must produce no warnings
- Add tests for any new functionality
- Keep the public API minimal

## Testing

Run the full test suite:

```bash
make test
```

Integration tests (which hit the real DuckDuckGo endpoint) require a build tag:

```bash
go test -tags=integration -v ./...
```

## Pull request process

1. Ensure `make check` passes (fmt + vet + test)
2. Add tests for new features or bug fixes
3. Update documentation if you change behavior
4. Keep PRs focused — one concern per PR

## Commit messages

This project uses [Conventional Commits](https://www.conventionalcommits.org/) for automated changelog generation via [git-cliff](https://git-cliff.org).

Format:

```
<type>(<scope>): <description>

[optional body]
```

**Types:**

| Type | Description |
|------|-------------|
| `feat` | New feature |
| `fix` | Bug fix |
| `docs` | Documentation changes |
| `perf` | Performance improvements |
| `refactor` | Code refactoring |
| `style` | Formatting, whitespace |
| `test` | Adding or updating tests |
| `chore` | Build, CI, tooling |
| `ci` | CI pipeline changes |
| `build` | Build system changes |

**Examples:**

```
feat: add timeout configuration for search client
fix: handle empty URL in extractRealURL
docs: update MCP client configuration examples
test: add coverage for rate limit retry path
ci: add govulncheck to CI workflow
```

The changelog is generated by `make changelog` or automatically during the release workflow.

## Reporting issues

- Use the [GitHub issue tracker](https://github.com/bcambl/ddg-mcp/issues)
- Include steps to reproduce, expected behavior, and actual behavior
- Include the output of `ddg-mcp --version` if applicable

## Developer Certificate of Origin (DCO)

This project uses the [Developer Certificate of Origin](DCO) (DCO v1.1). Every commit must include a `Signed-off-by:` trailer certifying that the contributor has the right to submit the code under the project's license.

**How to sign off:**

```bash
git commit -s
```

This automatically appends `Signed-off-by: Your Name <your@email>` to the commit message. You can also add it manually to any commit message.

**Example commit:**

```
feat: add timeout configuration for search client

Signed-off-by: Your Name <your.email@example>
```

Pull requests with commits missing the `Signed-off-by:` trailer will fail the DCO check in CI. See the [DCO](DCO) file for the full certification text.
